## Alat Internal: Marketing Dokter Laundry (`marketing.html`)

Halaman **terpisah** dari `index.html` (bukan bagian aplikasi kasir yang
dipakai pemilik toko laundry) — ini alat internal khusus untuk pemilik
platform (email-nya ada di `ADMIN_EMAILS`, bisa lebih dari satu — lihat
bagian "Lebih dari 1 akun Admin Platform" di bawah) memasarkan produk
**Dokter Laundry** sendiri. Login pakai akun Supabase yang sama dengan
aplikasi utama; kalau email-nya tidak ada di `ADMIN_EMAILS`, langsung
ditolak & di-sign-out.

Dibangun bertahap — fitur pertama yang sudah ada:

### LOW: link komunitas/hasil pencarian bisa berupa `javascript:` URI — `safeHref()`

Ditemukan di audit lanjutan (13 Oktober 2026). `marketing.html` punya
`innerHTML`-nya SENDIRI (file terpisah dari `index.html`/`js/*.js`,
TIDAK ikut tercakup audit XSS sebelumnya) — di 4 tempat, field `link`
(diisi bebas manual lewat form "Tambah Komunitas", atau hasil pencarian
online dari Serper API) dipakai langsung sebagai `href="${escapeHTML(...)}"`.
`escapeHTML()` cuma meng-escape karakter HTML (`&<>"'`) — itu TIDAK
menghalangi skema URL seperti `javascript:alert(1)` yang sama sekali
tidak mengandung karakter itu, jadi lolos begitu saja ke atribut `href`
dan tereksekusi saat link-nya diklik. Risiko di alat ini sendiri rendah
(cuma 2 akun `ADMIN_EMAILS` yang bisa akses sama sekali, lihat RLS
`marketing_communities`/`marketing_leads` — admin menyerang diri
sendiri/admin lain, bukan celah publik), tapi tetap pola yang salah
untuk dibiarkan.

Diperbaiki: tambah `safeHref(url)` — cuma izinkan skema `http://`/`https://`,
selain itu balik `'#'` (link mati, aman) — dipakai SEBELUM `escapeHTML()`
di keempat tempat (`resolveCommLink()` punya `link` untuk komunitas,
hasil pencarian `r.link` dari Serper API untuk komunitas maupun kontak
laundry). Diverifikasi langsung lewat browser headless sungguhan:
`javascript:`/`data:` URI diblokir jadi `'#'`, `http(s)://` (termasuk
huruf besar) tetap lolos apa adanya.

### Riset Komunitas

Daftar komunitas pemilik usaha laundry di Indonesia (asosiasi, grup
Facebook/WhatsApp/TikTok, forum) supaya bisa **bergabung & aktif** di sana
secara wajar — BUKAN alat untuk mengirim pesan promosi massal ke kontak
yang diambil sembarangan (itu sengaja tidak dibuat, lihat catatan di
halamannya sendiri — melanggar ToS platform & berisiko UU PDP).

Ada kolom cari (nama/catatan/kontak) + filter **Platform** dan **Daerah**
(opsi Daerah otomatis terisi dari data yang sudah tersimpan, bukan daftar
tetap) di atas daftar komunitas, plus tombol Reset untuk membersihkan
semua filter sekaligus.

Butuh tabel baru `marketing_communities` yang belum ada di database —
jalankan sekali di Supabase SQL Editor:

```sql
create table if not exists marketing_communities (
  id bigint generated by default as identity primary key,
  platform text not null default 'lainnya',
  nama text not null,
  daerah text,
  link text,
  jumlah_anggota text,
  kontak_admin text,
  catatan text,
  created_at timestamptz not null default now()
);

alter table marketing_communities enable row level security;

-- SENGAJA dibatasi cuma email di ADMIN_EMAILS (beda dari model permisif
-- registration_codes/payment_requests/app_branding) -- tabel ini murni data
-- operasional marketing pemilik platform, tidak ada alasan akun toko biasa
-- perlu baca/tulis ke sini sama sekali. Daftar email-nya HARUS sama persis
-- dengan ADMIN_EMAILS di js/00-globals.js/marketing.html/search-communities.js.
create policy "Cuma admin platform yang bisa akses data marketing"
on marketing_communities
for all
using ((auth.jwt() ->> 'email') in ('mukhlispertama@gmail.com', 'dokterlaundromat@gmail.com'));
```

### Cari Komunitas Online

Di atas daftar komunitas ada kartu "🔎 Cari Komunitas Baru secara Online" —
ketik kata kunci (mis. "komunitas laundry Bandung"), tekan Cari, hasilnya
pencarian internet **sungguhan** (bukan data yang ditulis Claude manual),
lalu tinjau tiap hasil dan tekan "+ Tambah ke Database" untuk membuka form
Tambah Komunitas dengan Nama/Link/Catatan sudah terisi otomatis dari hasil
pencarian (Platform & Daerah tetap harus diisi manual, dan semua field
masih bisa diedit sebelum disimpan — tidak ada yang masuk database tanpa
ditinjau dulu).

Pencariannya lewat [Serper.dev](https://serper.dev) (search API pihak
ketiga berbasis hasil Google Search — Google Custom Search API sendiri
sudah **tutup untuk pendaftar baru** per 2026 dan akan dimatikan total 1
Januari 2027, jadi tidak dipakai). Dipanggil lewat
`netlify/functions/search-communities.js`, BUKAN langsung dari browser ke
Serper — supaya `SERPER_API_KEY` tidak pernah ada di kode browser (kalau
ditaruh di sana, siapa saja bisa mencurinya dari DevTools dan menghabiskan
kuota berbayar kita). Function ini juga memverifikasi token Supabase Auth
pengirim request benar-benar salah satu email di `ADMIN_EMAILS`, jadi
orang lain yang menemukan URL function-nya langsung dari luar tetap
tidak bisa memakainya.

**Environment variables di Netlify** (Site settings → Environment
variables, bukan di kode/git):

| Nama | Contoh nilai | Keterangan |
|---|---|---|
| `SERPER_API_KEY` | `a1b2c3...` | Daftar gratis di [serper.dev](https://serper.dev) (2.500 pencarian/bulan gratis, lalu berbayar), buka **API Key** di dashboard lalu salin nilainya. |

`SUPABASE_URL` yang sama dengan fitur Midtrans ([pembayaran-midtrans.md](pembayaran-midtrans.md)) juga dipakai
function ini (kalau belum diisi, isi dulu). Sebelum `SERPER_API_KEY`
diisi, tombol Cari akan gagal dengan pesan error yang jelas — fitur lain
di halaman ini (daftar komunitas, filter, tambah/edit/hapus manual) tidak
terpengaruh sama sekali.

### Kontak Laundry (nomor WA & email usaha)

Tab terpisah dari Riset Komunitas — kalau Riset Komunitas isinya komunitas
untuk **bergabung & aktif**, tab ini isinya kontak bisnis laundry orang
per orang (nomor WA & email usaha) untuk dihubungi **satu per satu secara
personal** soal Dokter Laundry. **Bukan** alat kirim pesan massal
otomatis — tidak ada fitur kirim WA/email dari dalam app-nya sendiri,
cuma link `wa.me`/`mailto:` yang membuka aplikasi WA/email biasa untuk
dikirim manual satu per satu.

Sama seperti Riset Komunitas, ada kartu "🔎 Cari Kontak Laundry Online"
yang pakai search API (Serper.dev) yang sama — nomor HP & alamat email
di judul/cuplikan hasil pencarian **ditebak lewat regex** (ditandai
"Terdeteksi"), bukan dijamin akurat, jadi tetap harus ditinjau lewat form
Tambah Kontak (bisa diedit dulu) sebelum benar-benar tersimpan.

Nomor WA yang tersimpan otomatis jadi link `wa.me/...` (format nomor
dirapikan otomatis: `0812...` → `62812...`), email jadi link `mailto:`.
Ada checkbox "Sudah dihubungi" per baris supaya tidak menghubungi kontak
yang sama dua kali.

Butuh tabel baru `marketing_leads` — jalankan sekali di Supabase SQL
Editor:

```sql
create table if not exists marketing_leads (
  id bigint generated by default as identity primary key,
  nama text not null,
  telepon text,
  email text,
  daerah text,
  sumber_link text,
  catatan text,
  sudah_dihubungi boolean not null default false,
  created_at timestamptz not null default now()
);

alter table marketing_leads enable row level security;

-- Sama seperti marketing_communities: sengaja dibatasi cuma email di
-- ADMIN_EMAILS, bukan model permisif seperti registration_codes/payment_requests.
create policy "Cuma admin platform yang bisa akses data marketing"
on marketing_leads
for all
using ((auth.jwt() ->> 'email') in ('mukhlispertama@gmail.com', 'dokterlaundromat@gmail.com'));
```

Sebelum tabel ini ada, tab "Kontak Laundry" akan gagal memuat data (toast
error) — tab/fitur lain tidak terpengaruh.

### Analitik Pengunjung (📊 Analitik Pengunjung)

Tab baru **📊 Analitik Pengunjung** di `marketing.html` dan widget di
Pengaturan Admin Platform (`index.html`) untuk memantau trafik & statistik
pengunjung Dokter Laundry:

- **Ringkasan Angka Utama**: Total Kunjungan (Pageviews), Pengunjung Unik,
  Kunjungan Hari Ini, Pengunjung Unik Hari Ini, dan Total Klik Pendaftaran.
- **Filter Periode Waktu**: 7 Hari Terakhir, 30 Hari Terakhir, dan Semua Waktu.
- **Grafik Tren Harian**: Tampilan bar chart interaktif yang memperlihatkan tren
  kunjungan total & pengunjung unik per hari.
- **Rincian Perangkat & Browser Spesifik**: Identifikasi rinci seperti "Chrome di Android",
  "Safari di iPhone", "Edge di Windows", dll.
- **Pelacakan Event Pendaftaran**: Melacak pengunjung yang mengklik tab/tombol "Daftar"
  atau mengirim konfirmasi pendaftaran (`click_daftar`).
- **Identifikasi Akun Pengunjung**: Mencatat email dan nama akun pengguna secara otomatis
  apabila pengunjung sudah melakukan login / memiliki akun.

Pelacakan dilakukan secara otomatis & non-blocking saat pengunjung membuka
aplikasi, menggunakan `visitor_id` anonim persisten di `localStorage`, serta
pencegahan spam/pencatatan ganda dalam 1 sesi menggunakan `sessionStorage`.

Membutuhkan tabel `visitor_logs` di Supabase — lihat petunjuk SQL di
[docs/migrasi-database.md](migrasi-database.md#analitik-pengunjung-visitor_logs).

Tab lain di halaman ini (Konten Promosi, Landing Page, Program Referral)
baru placeholder ("Segera") — akan dikerjakan satu-satu sesuai permintaan.

### Lebih dari 1 akun Admin Platform

Akses Admin Platform (panel di Pengaturan, alat Marketing di atas, dan
fitur Cari Komunitas/Kontak Laundri Online) **bisa dipakai lebih dari 1
email** — diatur lewat daftar `ADMIN_EMAILS`, BUKAN 1 email tunggal lagi.

Untuk nambah/ganti admin, daftar emailnya harus diperbarui **persis sama**
di 4 tempat ini sekaligus (kalau cuma sebagian, perilakunya jadi
tidak konsisten antar fitur):

1. `ADMIN_EMAILS` di `js/00-globals.js` (aplikasi utama, `index.html`)
2. `ADMIN_EMAILS` di `marketing.html` (login alat Marketing)
3. `ADMIN_EMAILS` di `netlify/functions/search-communities.js` (gerbang function Cari Online)
4. RLS policy tabel `marketing_communities` & `marketing_leads` di Supabase — jalankan sekali di SQL Editor (aman dijalankan berapa kali pun, cukup ganti daftar email di dalam `in (...)` sesuai kebutuhan):

```sql
alter policy "Cuma admin platform yang bisa akses data marketing"
on marketing_communities
using ((auth.jwt() ->> 'email') in ('mukhlispertama@gmail.com', 'dokterlaundromat@gmail.com'));

alter policy "Cuma admin platform yang bisa akses data marketing"
on marketing_leads
using ((auth.jwt() ->> 'email') in ('mukhlispertama@gmail.com', 'dokterlaundromat@gmail.com'));
```

Catatan: ini cuma mengatur **siapa yang dianggap admin platform**, bukan
bikin akun baru di Supabase Auth — tiap email yang dimasukkan di daftar
ini tetap harus sudah punya akun (lewat Daftar seperti akun toko biasa)
sebelum bisa login dan dianggap admin.
